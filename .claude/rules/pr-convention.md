# PR 작성 규칙

PR 본문은 `.github/PULL_REQUEST_TEMPLATE.md` 템플릿을 따르되, 각 섹션은 아래 기준으로 작성한다.

## 🔍 PR 요약

말 그대로 summary. 이 PR이 뭘 하는지 1~2문장. 상세 내용 반복 금지.

## 🧠 의도 및 배경

요구사항을 쉬운 말로 담백하게 자연어 서술. 기술 용어 나열보다 "왜 필요한지"가 읽히게. 기획/디자인 맥락이 있으면 여기에.

## 🛠️ 주요 변경 사항

실제 구현 내용을 bullet로. 특히 **리뷰어가 신경 써서 봐야 하는 부분**을 명시:

- 구현했는데 애매하거나 자신 없는 부분
- 트레이드오프가 있었던 결정
- 사이드이펙트 가능성이 있는 변경

## 그 외

- 트러블슈팅/스크린샷 섹션은 해당 없으면 삭제
- 관련 이슈 번호는 `close #N` 형식으로 연결
