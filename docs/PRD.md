# PRD — 뽀또즈 (NEXTERS Gallery-100)

> **방치된 갤러리 사진 100장을 AI가 테마별 스티커로 만들어, 나만의 보드에서 재미있게 회고하는 포토 리캡 서비스**

| 항목 | 내용 |
| --- | --- |
| 프로젝트 | NEXTERS Gallery-100 (8주) |
| 컨셉 | Stickering: 스티커 스타일로 사진 그루핑 |
| 플랫폼 | 웹뷰 앱 |
| 서비스명 | 뽀또즈 (가칭, 최종 확정 전 — Open Questions 참고) |
| 디자인 | 피그마 — 최종 아이디어 섹션 |

## 용어

문서 전체에서 아래 용어를 일관되게 사용한다.

- **원본 사진** — 사용자 갤러리의 사진 그 자체.
- **근접 촬영 그룹** — 촬영 시각이 가까운 원본 사진들의 묶음. 그룹화 규칙은 [사진 선정과 근접 촬영 그룹](#사진-선정과-근접-촬영-그룹) 참고.
- **대표 사진** — 근접 촬영 그룹에서 그룹을 대표하는 1장. AI 분석과 스티커 생성에는 대표 사진만 사용한다.
- **분석 단위** — 근접 촬영 그룹의 대표 사진 1장, 또는 그룹화되지 않은 단일 사진 1장. 각각 1개로 계산한다.
- **분석용 이미지** — 대표 사진과 그룹화되지 않은 단일 사진. 테마 분류, 스티커 생성, 리캡 콘텐츠 생성에 사용.
- **리캡 열람용 이미지** — 근접 촬영 그룹에서 대표 사진을 제외한 나머지 사진. 리캡에서 그룹을 펼쳤을 때 보여주는 용도.
- **테마** — AI가 분석 대상 사진을 묶은 분류 단위 (보드당 4~6개).
- **대표 스티커** — 테마당 1개 생성되는 스티커.

> **사진 수 기준:** 별도 표기가 없는 사진 수와 장수는 근접 촬영 그룹의 대표 사진을 포함한 **분석 대상 이미지 수**(=분석 단위 수)를 의미한다. 그룹 내 나머지 원본 사진 수는 테마 리캡의 그룹 배지와 테마 요약 정보에서만 별도로 표시한다.

## 1. 문제와 타깃

### 배경

- 현대인은 스마트폰 갤러리에 **평균 2,795장**의 사진을 쌓아두고 있다. (출처)
- 하지만 찍은 그날 이후 **80%의 사진은 다시 열어보지 않으며**, 오히려 너무 많은 사진 때문에 압도감을 느낀다.
- 클라우드의 무한한 저장 공간은 **'디지털 호딩(디지털 저장 강박)'**을 낳았다. 언젠가 볼 것이라며 모든 순간을 캡처하지만, 데이터가 비대해져 결국 어떤 추억도 쉽게 꺼내볼 수 없는 역설에 놓여 있다. **데이터는 쌓여가지만, 정작 나의 이야기는 잊혀지고 있다.**
- 한편 "내 데이터를 위트있게 읽어주는" 서비스가 부상 중이다(Spotify Wrapped, 2025 Wrapped – Photo Recap 등). 다만 이들은 대부분 **연말 1회성 이벤트**에 그치고, 결과물도 텍스트/통계 중심이라 **"소장하고 싶은 이미지"**까지는 채워주지 못한다. → 여기가 우리의 기회다.

### Pain Point

1. **다시 볼 계기가 없는 갤러리** — 사진은 계속 쌓이지만 특정 사진을 찾을 때 외에는 지난 기록을 다시 탐색할 계기가 없다.
2. **파편화된 기록** — 한 장씩 보면 의미가 있지만, 사진들이 서로 연결되지 않아 그 기간의 관심사와 일상이 한눈에 드러나지 않는다.

### 타깃

- 평소에 사진을 자주 찍지만 다시 보지는 않는 사람
- 지난 사진을 직접 선별하거나 묶어서 돌아보지 않는 사람
- 개인화된 결과물을 꾸미거나 저장하는 데 관심이 있는 사람

> **페르소나:** 한 달에 수백 장의 사진과 스크린샷을 저장하지만, 갤러리를 다시 여는 건 사진을 찾거나 보낼 때뿐인 20대 직장인. 가끔 "지난달에 뭐 했더라?"고 생각하지만 수백 장을 직접 훑어볼 엄두는 내지 못한다.

## 2. 핵심 경험 — Stickering

> 방치된 사진 100장을 AI가 몇 개의 테마로 엮고, 사용자가 스티커 보드를 꾸미며 지난 일상을 발견하는 포토 리캡 경험

- **AI가 찾아줍니다:** 100장 속 반복되는 사람, 장면, 관심사를 테마로 묶는다.
- **스티커로 보여줍니다:** 각 테마를 대표하는 사진을 소장하고 싶은 시각 요소로 만든다.
- **사용자가 완성합니다:** 스티커를 직접 배치하며 나만의 보드를 만든다.
- **눌러서 회고합니다:** 각각의 테마 안에서 원본 사진과 해석을 다시 본다.

## 3. 전체 사용자 흐름

```
사진 업로드 → 스티커 생성(분석 로딩) → 스티커 보드 → 테마 리캡
```

| 단계 | 화면 | 핵심 동작 |
| --- | --- | --- |
| ① 사진 업로드 | 업로드 | 최근 사진 기반 100개 분석 단위 자동 선정, 최대 10개 제외 |
| ② 로딩 | 전송/분석/생성 대기 | 이미지 압축·전송, 테마 분류, 스티커·리캡 콘텐츠 생성 |
| ③ 스티커 보드 | 보드 | 테마별 대표 스티커 배치·편집, 스티커 선택 시 리캡 이동 |
| ④ 테마 리캡 | 리캡 | 테마의 분위기·공통점 확인, 원본 사진 재열람 |

## 4. 기능별 상세 정책

### 사진 선정과 근접 촬영 그룹

- 최근 갤러리 사진을 기반으로 **100개의 분석 단위**를 자동 선정한다.
- 촬영 시각이 가까운 사진은 근접 촬영 그룹으로 묶으며, 그룹당 대표 사진 1장만 AI 분석 대상으로 사용한다.
- 최근 사진 기준으로 100개의 분석 단위를 확보할 수 없는 사용자는 생성할 수 없으며, 서비스는 생성 불가 안내를 제공한다.

**그룹화 규칙:**

- 사진을 촬영 시각순으로 정렬한 뒤, 아직 그룹화되지 않은 첫 사진의 촬영 시각을 기준으로 이후 **5분 이내**의 사진을 하나의 근접 촬영 그룹으로 묶는다. 다음 그룹은 직전 그룹에 포함되지 않은 첫 사진부터 새로 시작한다.
- 그룹 내 촬영 시각이 가장 빠른 사진을 대표 사진으로 선정한다.
- 업로드 화면에는 대표 사진만 표시한다. 그룹의 나머지 사진은 화면에 표시하지 않지만 그룹에 포함된 상태를 유지하며, 대표 사진이 변경되거나 리캡을 생성할 때 함께 사용된다.
- 대표 사진만 스티커 생성 대상으로 사용한다.
- 그룹 대표 사진과 그룹화되지 않은 단일 사진은 각각 분석 단위 1개로 계산한다.

> **초기 가설값:** 근접 촬영 그룹화 기준은 5분. 내부 사진 세트 테스트를 통해 그룹화 정확도와 최종 사진 구성을 확인한 뒤 조정한다.

> **예상 엣지케이스:** 촬영 시각만으로 연속 촬영을 추정하므로, 짧은 시간 안에 서로 다른 대상을 촬영한 경우 하나의 그룹으로 잘못 묶이거나, 같은 대상을 오랜 시간 촬영한 경우 여러 그룹으로 분리될 수 있음. MVP에서는 시간 기반 정책을 우선 적용하고, 필요 시 사진 유형 및 이미지 유사도 비교를 추가.

### 사진 제외와 대표 사진 교체

- 사용자는 분석 단위를 **최대 10개**까지 제외할 수 있으며, 최종 **90~100장**이 분석·생성 단계로 전달된다.
- 그룹화되지 않은 사진을 제외하면 해당 사진만 제외한다.
- 근접 촬영 그룹의 대표 사진을 제외하면 그룹 내에서 촬영 시각이 다음으로 빠른 사진을 새로운 대표 사진으로 선정한다.
- 그룹의 모든 사진이 제외된 경우 해당 그룹을 분석 대상에서 제거한다.

> **초기 가설값:** 제외 가능 개수는 최대 10개. 내부 사진 세트 테스트를 통해 조정한다.

### 이미지 전송과 생성 (로딩)

- 사용자가 확정한 사진을 압축·전송하고, 테마 분류·스티커 생성·테마 리캡 콘텐츠 생성을 진행하는 동안 노출되는 대기 화면이다.
- 사용자가 현재 처리 중임을 인지하고 이탈하지 않도록, 이미지 전송 과정에서 먼저 산출할 수 있는 정보를 활용해 로딩 콘텐츠를 제공한다. 로딩 콘텐츠에는 촬영 일시, 이미지 방향·비율, 밝기, 채도, 대표 색상 등의 정보를 활용할 수 있다.
- 이미지 전송과 모든 생성 작업이 완료되면 스티커 보드로 이동한다.

**이미지 이원화:**

| 구분 | 대상 | 용도 | 처리 품질 |
| --- | --- | --- | --- |
| **분석용 이미지** | 근접 촬영 그룹의 대표 사진과 그룹화되지 않은 단일 사진 | 테마 분류, 스티커 생성, 한 줄평·배경 이미지 등 리캡 콘텐츠 생성 | 이미지 분석과 스티커 생성이 가능한 품질 유지 |
| **리캡 열람용 이미지** | 근접 촬영 그룹에서 대표 사진을 제외한 나머지 사진 | 리캡에서 그룹을 펼쳤을 때 사진 전체를 보여주는 용도 | 분석용 이미지보다 낮은 해상도와 용량으로 처리 가능 |

**전송 및 결과 제공 정책:**

- 분석용 이미지와 리캡 열람용 이미지에는 서로 다른 압축 규격을 적용할 수 있다.
- MVP에서는 분석용 이미지와 리캡 열람용 이미지의 전송, 테마 분류, 스티커 생성 및 테마 리캡 콘텐츠 생성이 모두 완료된 이후 보드를 제공한다.
- 전체 대기 시간이 과도하게 길다고 판단되는 경우, 실제 측정 결과를 기준으로 처리 시간이 가장 긴 작업부터 후속 백그라운드 처리로 분리하고 보드 제공 시점을 재조정한다.

> **초기 시간 가설:** 전체 처리 시간은 약 20초로 예상하지만 아직 검증되지 않은 값이다. 클라이언트 이미지 압축, 분석용·열람용 이미지 전송, 테마 분류, 스티커 생성, 리캡 콘텐츠 생성에 걸리는 시간을 각각 측정한 뒤 로딩 콘텐츠의 종류와 노출 주기를 확정한다.

> **예상 엣지케이스:** 원본 이미지의 해상도·포맷과 기기 성능에 따라 클라이언트 압축 시간이 달라질 수 있다. 근접 촬영 그룹에 포함된 사진이 많으면 리캡 열람용 이미지 수가 크게 증가해 전체 전송 시간이 길어질 수 있다. 네트워크 지연이나 일부 이미지 전송·생성 실패가 발생할 수 있으므로, 실제 테스트 결과를 바탕으로 압축 규격과 전송 순서, 재시도 방식을 확정한다.

### 테마 분류와 스티커 생성

**테마 분류 정책:**

- AI가 분석 대상 사진을 **4~6개의 테마**로 분류한다. 보드의 탐색성과 시각적 밀도를 위해 테마 수를 최소 4개, 최대 6개로 구성하는 것을 기본 정책으로 둔다.
- 모든 분석 대상 사진은 가장 연관성이 높은 하나의 테마에 귀속한다.
- 근접 촬영 그룹의 대표 사진이 특정 테마에 배정되면, 해당 그룹의 나머지 사진도 대표 사진과 동일한 테마에 귀속한다. 그룹의 나머지 사진은 테마 분류에는 직접 사용하지 않는다.
- 자연스럽게 도출된 테마 수가 4개 미만인 경우, 기존 군집을 재분류하거나 가장 규모가 큰 테마를 하위 공통점 기준으로 추가 분리하여 최소 4개를 맞춘다.

**애매한 사진 처리 정책:**

- 특정 테마와의 연관성이 낮은 사진은 테마명, 대표 스티커, 한 줄평, 배경 이미지 등 대표 콘텐츠를 생성하는 근거에서는 제외할 수 있다.
- 해당 사진은 결과에서 제거하지 않고, 귀속된 테마의 사진 목록에는 포함한다.

**스티커 생성 정책:**

- 테마 생성 후에는 해당 테마를 가장 잘 대표하는 시각적 재료를 판단하여, 아래 세 형식 중 하나로 대표 스티커 1개를 생성한다.
- 테마 유형과 스티커 형식을 고정적으로 매핑하지 않고, 각 테마의 대표성을 기준으로 결정한다.

| 유형 | 적용 조건 | 생성 방식 | 예시 |
| --- | --- | --- | --- |
| **피사체형 이미지 스티커** | 특정 피사체가 테마를 대표하고, 배경에서 분리 가능한 경우 | 대표 사진에서 피사체를 분리해 스티커로 생성 | 사람, 동물, 음식, 제품 |
| **장면형 이미지 스티커** | 개별 피사체보다 사진 전체의 장면·분위기가 테마를 대표하는 경우 | 대표 사진을 유기적인 형태로 크롭해 스티커로 생성 | 풍경, 야경, 공간 |
| **텍스트형 스티커** | 사진 속 텍스트가 테마의 정체성을 가장 잘 드러내는 경우 | 대표 원문을 추출해 사용하고, 적절한 원문이 없으면 테마명 또는 짧은 생성 문구 사용 | 메신저 캡처, 메모, 티켓, 문서 |

> **초기 가설값:** 보드의 기본 테마 수는 4~6개로 설정한다. 이 범위는 사용자 경험을 위한 초기 가설이며, 실제 사진 분포에 따라 자연스러운 테마 수는 이보다 적거나 많을 수 있다. 내부 테스트로 스티커 밀도, 탐색성, 분류 납득도를 검증한 뒤, 억지 분류가 발생하는 경우 테마 수 범위 또는 분류 규칙을 조정한다.

> **예상 엣지케이스:** 사진 분포가 한두 개 주제에 과도하게 집중된 경우, 최소 4개 테마 정책으로 인해 유사한 사진이 여러 테마로 억지 분리되거나 의미가 약한 소규모 테마가 생성될 수 있다. 반대로 사진 성격이 지나치게 다양할 경우, 6개 이내로 묶는 과정에서 서로 이질적인 사진들이 하나의 테마로 합쳐질 수 있다. 또한 대표성이 뚜렷한 피사체나 문구를 찾지 못하면 스티커가 테마를 충분히 설명하지 못할 수 있다.

### 스티커 보드

- 하나의 테마는 하나의 대표 스티커와 연결되며, 스티커를 선택하면 해당 테마의 리캡으로 이동한다.

**보드 구성 및 편집 정책:**

- 생성된 스티커는 보드 영역 안에서 일정한 규칙에 따라 자동 배치되며, 사용자는 각 스티커의 위치와 크기를 조정할 수 있다.
- 제목과 부제는 자동 생성 후 사용자가 수정할 수 있다.
- 새로운 사진 묶음으로 생성할 때마다 새로운 보드 1개를 생성한다.

### 테마 리캡

- 사용자가 스티커 보드에서 특정 스티커를 선택하면, 해당 스티커와 연결된 테마 리캡 페이지로 이동한다.
- 테마 리캡은 해당 테마의 분위기와 공통점을 보여주고, 테마에 포함된 사진을 다시 확인하게 하는 화면이다.
- 하나의 테마당 하나의 리캡 페이지를 생성한다.

**리캡 구성:**

| 구역 | 목적 | 포함 요소 |
| --- | --- | --- |
| **테마 대표 영역** | 해당 테마의 분위기와 정체성을 직관적으로 보여줌 | 테마명, 대표 스티커, 한 줄평, 배경 이미지 |
| **테마 요약 정보** | 사용자가 어떤 사진들이 하나의 테마로 묶였는지 이해하도록 돕기 | 분석 단위 수, 그룹 포함 실제 원본 사진 수, 대표 키워드 또는 공통점 |
| **테마 사진 목록** | 해당 테마에 포함된 사진을 다시 보고, 분류 결과를 확인하게 함 | 분석 대상 사진 목록, 근접 촬영 그룹 배지, 그룹 펼침 기능 |

**테마 대표 영역:**

- 페이지 최상단에서 해당 테마의 분위기와 정체성을 보여준다.
- 한 줄평은 사진의 종류를 그대로 설명하기보다, 사진에서 발견한 공통점을 가볍게 해석하는 역할을 한다.
  > 예: "이번 달의 약속은 대부분 식탁 위에서 시작됐어요."

**테마 요약 정보:**

- 사용자가 어떤 사진들이 하나의 테마로 묶였는지 이해할 수 있도록 기본 정보를 제공한다. 포함 요소는 리캡 구성 표를 따른다.
- 분류 근거를 별도의 설명문으로 반드시 제공하지는 않지만, 한 줄평이나 요약 정보에서 사진들의 공통점이 어느 정도 드러나도록 한다.

**테마 사진 목록 및 표시 정책:**

- 해당 테마에 배정된 분석 대상 사진을 촬영 시각순으로 기본 노출한다.
- 근접 촬영 그룹은 대표 사진 1장과 `×4` 형태의 장수 배지로 표시한다. 배지 숫자는 대표 사진을 포함한 그룹 전체 장수다.
- 사용자가 그룹을 펼칠 때만 그룹 내 나머지 사진을 노출하며, 이 사진들은 리캡 열람용 이미지로 제공한다. ([이미지 이원화](#이미지-전송과-생성-로딩) 참고)

**리캡 콘텐츠 생성 정책:**

- 배경 이미지는 해당 테마의 분석용 이미지만을 재료로 사용하며, 원본의 주요 피사체와 장면이 다른 대상으로 왜곡되지 않는 범위에서 생성한다.

**한 줄평 생성 정책:**

- 한 줄평은 사진에서 관찰 가능한 내용과 반복 패턴을 근거로 작성한다. 사진의 종류를 단순히 나열하기보다 공통점을 가볍게 해석하는 톤을 지향한다.
- 다만 외모 평가, 인간관계 단정, 성격·심리·건강 상태에 대한 진단처럼 사용자가 불쾌하거나 사실로 오해할 수 있는 표현은 생성하지 않는다.

> **예상 엣지케이스:** 테마의 공통점이 약한 경우 한 줄평이 지나치게 일반적이거나 실제 사진 묶음의 특징을 충분히 설명하지 못할 수 있다. 근접 촬영 그룹이 큰 경우 그룹을 펼쳤을 때 사진 수가 많아져 리캡 로딩 시간이 길어질 수 있으며, 저해상도 열람용 이미지의 품질 저하가 발생할 수 있다. 배경 이미지 생성 과정에서도 원본 분위기를 충분히 살리지 못하거나 시각적 완성도가 기대에 미치지 못할 수 있으므로, 내부 테스트를 통해 표현 방식과 품질 기준을 보완한다.

## 5. MVP 핵심 가설 및 성공 기준

검증 방법, 성공 기준은 UT 시작 전 확정.

| 가설 | 분류 | 가설 | 검증 방법 | 성공 기준(가설값·조정 필요) |
| --- | --- | --- | --- | --- |
| H1 | **분류 납득** | AI가 나눈 테마와 대표 사진 선정이 사용자에게 납득된다 | 전체 분류 만족도 설문 + 각 테마를 확인하며 해당 테마에 어울리지 않는다고 판단한 사진 수와 이유 기록 | 참여자 과반수가 전체 분류를 대체로 납득하고, 각 참여자가 명백한 오분류로 판단한 사진이 전체 분석 대상의 10% 이하일 것 |
| H2 | **소장 가치** | 완성된 스티커 보드는 소장하고 싶을 만큼 매력적이다 | 저장 의향 설문, 보드 편집 행동, 저장 기능 사용 관찰 | 참여자 과반수가 결과물을 저장하고 싶다고 응답하고, 실제 저장 기능이 제공되면 과반수가 별도 유도 없이 저장할 것 |
| H3 | **회고 재미** | 리캡이 사진을 다시 보게 만드는 재미있는 회고 경험을 준다 | 안내 없이 진입한 리캡 수, 그룹 펼침·사진 열람 행동, 회고 경험 만족도 및 자발적 반응 관찰 | 참여자 과반수가 별도 지시 없이 2개 이상의 리캡을 열람하고, 과반수가 사진 그룹 펼치기·사진 재열람 행동을 보일 것 |
| H4 | **대기 UX** | 분석 문구+애니메이션이 20초+ 로딩을 버티게 한다 | 로딩 시뮬레이션 중 이탈·뒤로 가기 시도, 화면 주시 및 콘텐츠 인지 여부, 체감 대기 시간 평가 | m명 중 n명 이상이 로딩 도중 이탈을 시도하지 않고, k명 이상이 대기 시간을 "감내 가능하다"고 평가할 것 |

> **성공 기준 원칙:** 성공 기준은 %가 아닌 "m명 중 n명"과 같은 식으로 한다. UT 표본이 충분히 많지 않아 % 사용 시 불필요한 정밀함과 애매한 해석이 생길 수 있다. 참여 인원이 확정되면 모든 가설의 기준(현재 "과반수"로 표기된 것 포함)을 정수로 일괄 고정한다.

### 후속 탐색 항목

| 분류 | 탐색 질문 | 검증 방법 | 기대 산출물 |
| --- | --- | --- | --- |
| **반복 사용** | 첫 보드 이후 어떤 조건에서 새 보드를 다시 만들고 싶은가? | `신규 사진 누적`, `정기 생성`, `과거 사진 생성` 시나리오 비교 인터뷰 | 후속 버전의 반복 생성 조건과 우선순위 |

> **반복 사용을 후속 탐색으로 분리한 이유:** 반복 생성을 위해서는 과거 사진 선택이나 신규 사진 누적 감지 또는 리마인더, 생성 히스토리 등 추가 기능이 필요해 MVP 범위가 커질 수 있다. 따라서 첫 보드 경험을 우선 검증한 뒤 반복 방식을 결정한다.

## 6. MVP 범위 — 💡 제안 (팀 논의 필요)

### Must

| 영역 | 포함 항목 | 근거 |
| --- | --- | --- |
| 사진 선정 | 최근 사진 기반 100개 분석 단위 자동 선정, 근접 촬영 그룹화, 대표 사진 선정, 최대 10개 제외, 대표 사진 제외 시 승계 | 분류에 들어갈 입력을 구성하는 필수 플로우 |
| 사진 부족 처리 | 필요한 분석 단위를 확보하지 못한 경우 생성 제한 및 안내 | 정상적으로 결과를 만들 수 없는 조건에 대한 필수 정책 |
| 테마 분류 | 분석 대상을 4~6개 테마로 분류, 각 분석 단위를 하나의 테마에 귀속, 그룹 내 사진은 대표 사진과 동일한 테마에 귀속 | H1 `분류 납득`의 직접 검증 대상 |
| 애매한 사진 처리 | 어떤 테마에도 명확히 맞지 않는 사진의 귀속·대표 콘텐츠 반영 여부에 대한 기본 규칙 | 이 정책이 없으면 분류 결과와 리캡 사진 수가 일관되지 않음 |
| 스티커 생성 | 테마당 대표 스티커 1개 생성, 피사체형·장면형·텍스트형 지원 | H2 `소장 가치`를 만드는 핵심 결과물 |
| 스티커 폴백 | 피사체 분리·OCR 등에 실패해도 최소 하나의 스티커를 제공할 수 있는 대체 방식 | 스티커 누락 시 보드와 리캡 진입 구조가 깨짐. 정확한 폴백 순서는 기능명세에서 확정 |
| 보드 구성 | 스티커 자동 배치, 위치·크기 조정, 제목 자동 생성 및 수정, 기간·분석 사진 수 표기 | 사용자가 결과물을 직접 완성하는 핵심 경험 |
| 보드 저장 | 완성된 보드를 이미지로 저장. 저장 산출물 범위(배경화면만, 전체를)는 디자인 시안 확정 후 정의 | H2를 의향뿐 아니라 실제 저장 행동으로 검증하기 위해 필요 |
| 리캡 기본 구성 | 테마명, 대표 스티커, 한 줄평, 분석 단위 수, 그룹 포함 원본 수, 대표 키워드 또는 공통점 | H1과 H3를 검증하는 핵심 콘텐츠 |
| 리캡 사진 목록 | 분석 대상 사진의 촬영 시각순 노출, 그룹 장수 배지, 그룹 펼침 | H3 `회고 재미`와 분류 납득을 확인하는 핵심 기능 |
| 로딩 | 처리 상태 안내, 1차 사진 정보 기반 콘텐츠, 기본 애니메이션 | H4 `대기 UX`를 검증하고 빈 화면 이탈을 방지 |
| 기본 실패 처리 | 업로드·생성 실패 안내와 사용자 재시도, 일부 생성 실패 시 기본 폴백 | 한 번의 UT 세션이 오류로 중단되지 않기 위한 최소 방어 |
| 안전·개인정보 | 민감 사진 수동 제외, 한 줄평 금지 표현 가드레일, 업로드 이미지 보관·삭제 정책 | 실제 개인·타인 사진을 다루므로 기능 검증보다 앞서는 필수 조건 |

### Should

| 영역 | 포함 항목 | 근거 |
| --- | --- | --- |
| 보드 부제 | 부제 자동 생성 및 수정 | 결과물 완성도를 높이지만 제목만으로도 H2 검증 가능 |
| 리캡 배경 비주얼 | 테마 사진을 활용한 AI 배경 이미지 생성 | 리캡 몰입도를 높이지만 H1·H3 검증에는 필수 아님. 미완성 시 고정 템플릿이나 대표 사진 기반 배경으로 대체 가능 |
| 생성 복구 | 화면 이탈 후에도 서버 작업 유지, 재진입 시 생성 결과 복구 | 실제 사용 안정성에는 중요하지만 초기 UT에서는 기본 실패 처리로 대체 가능 |
| 민감 이미지 자동 감지 | 신분증·문서·민감 텍스트 등의 자동 경고 또는 제외 제안 | 수동 제외로 기본 안전은 확보 가능 |
| 품질 최적화 | 이미지 압축 규격, 스티커 추출 품질, 한 줄평 톤 튜닝 | 기본 품질 확보 이후 성능과 완성도를 높이는 작업 |
